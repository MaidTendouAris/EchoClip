# 缓存上限与采样率（0.7.3+14）

## 保留规则

Windows 与 Android 共用 Rust 分片缓存。正常分片长度为 60 秒，达到时长上限即淘汰跨入过期边界的最早完整分片，包含恰好达到上限的时刻。以 30 分钟配置为例：29:59 → 29:00 → 29:01；继续录制 42 秒后暂停，缓存为 29:42，恢复读取和导出的音频时长也为 29:42。

总缓存显示直接读取核心按实际 PCM 样本数计算的可用时长；界面只对本次录音的计时器做平滑推进，不再自行增加或截断总缓存值。恢复已有缓存时也按新边界清理旧分片。

正在导出的文件继续受保护，防止破坏已经选定的音频；其过期部分不计入可用缓存时长，导出释放后再删除。设置中的磁盘缓存大小仍包含这些暂时保留的文件。分片删除遇到临时文件锁时保留元数据供重试。

边界查询使用已排序分片的二分查找；状态更新不扫描磁盘，保留之前长时间录音的性能修复。

## 设置

- 缓存范围为 5–1440 分钟。输入越界会归入边界值；Windows / Android 读取旧的低于 5 分钟配置时使用 5 分钟。
- 采样率选项：8、16、24、44.1、48 kHz。两端配置校验接受 44100，界面按 44.1 kHz 显示。
- 中文、英文提示均同步。录制中的音频设置继续在下次启动录音时生效。

## 验证

新增核心测试覆盖 30 分钟边界的物理删除、暂停及缓存恢复、不同回调长度的多次淘汰、旧超限缓存恢复和 44.1 kHz WAV 头及 PCM 内容。已有导出锁定及删除重试测试按整片淘汰规则更新。

新增 Flutter 测试覆盖原生查询延迟时总缓存不自行增长、淘汰后的时长回落及暂停稳定、5–1440 输入限制和 44.1 kHz 实际菜单选择。
